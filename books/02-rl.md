## ○ 先补一级台阶：RL 的最小闭环

> [!IMPORTANT]
> **本章问题**：RL 这个词底下，最小的一件事是什么？

第一次接触 RL 会先撞上一串缩写：RLHF、PPO、DPO、GRPO、Reward Model、Agentic RL。它们不是几个平行的概念，而是同一条链路在不同环节上的不同做法。先把链路本身定下来，缩写才有归属。

RL 作用于大模型时，一轮更新主要包含四步：

| 环节 | 在做什么 | 术语 |
|-|-|-|
| **采样** | 用当前模型对一批 prompt 各生成若干条输出 | rollout |
| **打分** | 判断每条输出好不好，给出一个标量分数 | reward（奖励） |
| **估计优势** | 判断这条输出比「同一个 prompt 下通常的水平」好多少 | advantage（优势） |
| **更新策略** | 提高优势为正的输出的生成概率 | 策略更新 |

「强化学习」说的就是靠奖励信号调整生成概率这一整套机制。后面所有方法名，都是这四步里某一步的不同实现。

这条链路里最不确定的是第二步「打分」——**分数是否真的代表你想要的目标，决定了后面三步全都在优化什么。** 第三章会看到，训练分数上涨而实际能力没变的问题，几乎都出在这里。

## 一、RL 在大模型训练里扮演什么角色？

> [!IMPORTANT]
> **本章问题**：已有预训练和 SFT，为什么还要再来一步 RL？

可以把大模型训练理解成三个连续的阶段：

**预训练 → SFT（监督微调） → RL（强化学习 / 后训练优化）**

预训练阶段，模型阅读大量文本，学到语言规律、知识和基本的表达能力。它像一个读过很多书的人，知道很多内容，但还不一定知道如何和人协作完成任务。

SFT 解决的是「怎么回答」的问题。模型开始看到用户、助手、系统等不同角色的对话，学习按指令回答、按格式输出、完成翻译、总结、代码生成等任务。[《LLM训练-SFT》](https://zhuanlan.zhihu.com/p/809229182)里有一个区分：预训练更像「学习知识」，SFT 更像「学习做题」。它讨论了任务类型、数据多样性和真实用户日志，说明模型的指令能力并不是凭空产生的，而是被一条条具体数据塑造出来的。

但只有 SFT 仍然有局限。因为现实中的「好回答」往往没有唯一标准：一道开放题的两个答案，可能都没有事实错误，但一个更清晰、更有帮助；代码看起来都合理，但只有一个能真正运行；Agent 调用了很多工具，但不一定完成了任务。

这些例子指向同一件事——**SFT 的优化目标是「像参考答案」，而很多任务的好坏无法写成参考答案**。它取决于结果、偏好或外部判定。这正是 RL 进入后训练的位置：不再模仿既定答案，而是根据「结果好不好」调整行为。

[《SFT、RLHF、DPO、IFT —— LLM 微调的进化之路》](https://zhuanlan.zhihu.com/p/710652762) — 边路腰刀 · 🟢 把这条演进线一次讲完：SFT 学的是示例，RLHF 及相关方法学的是偏好和评价。读到这里，三个阶段的分工会更清楚。

如果想先建立全局视野，[《全景解读 LLM 后训练技术》](https://zhuanlan.zhihu.com/p/30201040247) — tomsheep · 🟢 可以作为这一部分的起点。它把后训练放在「知识精炼、能力对齐、推理增强」的框架里理解，也能看到 RL 并不是孤立存在，而是与微调、评测和测试时推理一起塑造模型能力。

## 二、反馈怎么变成模型的能力更新？

> [!IMPORTANT]
> **本章问题**：分数打出来之后，怎么变成模型参数的改变？

上一章确定了 RL 的位置，这一章拆开那条最小闭环。顺序是：先看一次更新的完整链路（2.1），再看分数本身从哪来（2.2），最后看各家方法在哪些环节上做了不同取舍（2.3）。

### 2.1 一次更新里发生了什么

**采样（rollout）**：用当前模型对一批 prompt 各采样若干条输出。这些输出连同打分结果，构成这一轮的训练数据。

**打分（reward）**：给每条输出一个标量分数。分数从哪来是 2.2 的主题。

**估计优势（advantage）**：只知道「这条输出得了 0.8 分」是不够的——不同 prompt 的难度差异很大，绝对分数之间本就不可比，就像不同科目的 80 分含金量并不相同。真正驱动更新的，是它比「同一个 prompt 下通常的水平」高多少，这个差值叫优势。问题在于「通常能拿多少」这个基线怎么来，这里出现了两种路线：

- **PPO** 额外训练一个价值模型（critic），专门预测「给定当前前缀，后续大概能拿多少分」，用它作为基线。
- **GRPO** 省掉这个模型：对同一个 prompt 采样一组输出（比如 8 条），直接用这一组的均值和标准差做归一化，`优势 = (该条得分 − 组内均值) / 组内标准差`。

> 价值模型是 PPO 与 GRPO 最核心的结构差异。它要多占一份显存和一次前向，本身也需要训练收敛——这是 GRPO 出现的主要动机。
> 
> 代价发生在组内归一化自身的稳定性上。组内样本数偏小时，均值和标准差的估计就不准；更极端的情况是这一组输出全对或全错，归一化后所有优势都接近 0，这一组实际上不产生梯度。DAPO 等后续工作里的动态采样，正是针对这一点。

**更新策略**：提高优势为正的输出的生成概率，降低优势为负的。PPO 在这里加了两道约束：

- **clip**：限制单步更新的幅度，防止一次梯度把策略推得太远。上界设得过紧会带来一个副作用——模型迅速收敛到少数几种高分解法，输出多样性下降（即熵坍塌），探索能力随之减弱。
- **KL 惩罚**：约束新策略与原始模型的分布距离。

KL 那道约束的作用是防止模型为拿高分而偏离原始分布太远——典型表现是语言能力退化、输出模板化，或者直接钻奖励函数的空子（第三章会看到具体案例）。

这两道约束让 PPO 的每次更新幅度受限、收敛偏慢，但也让它不容易被训崩。这是它在长程、奖励稀疏且难验证的任务上仍被优先选择的原因。

### 2.2 分数从哪来：奖励模型，还是可验证信号？

第二步的分数来源，几乎决定了 RL 能用在哪类任务上。目前有两条路：

**奖励模型打分（RLHF）**

先训练一个模型来拟合人类偏好，再用它给输出打分。训练方式是准备偏好对：同一个 prompt 的两个回答，由标注者指出哪个更好，然后优化一个排序目标，让模型给 chosen 的分数高于 rejected（Bradley-Terry 形式的损失）。

它能处理「哪个回答更有帮助」这类无法写成规则的主观判断。局限也在这里：评分标准是学出来的，标注覆盖不到的地方它只能外推，而模型会主动去找这个外推区间里的高分区域。

**可验证奖励（RLVR）**

不做主观判断，只看可程序化判定的结果：数学题的答案是否正确、单元测试是否通过、代码能否编译运行。这类信号不需要训练奖励模型，成本远低于人工标注，也不存在标注者偏差。

RLVR 全称 Reinforcement Learning with Verifiable Rewards。用规则奖励训数学和代码的思路在此之前就有先例，DeepSeek-R1 的意义就在于把它推到了主流——它证明了只靠可验证信号就能激发出长链推理能力。

|  | 奖励模型打分 | 可验证奖励 |
|-|-|-|
| 信号来源 | 学出来的偏好模型 | 程序 / 规则判定 |
| 适用任务 | 开放式写作、对话、主观质量 | 数学、代码、有明确判定标准的操作 |
| 主要成本 | 标注 + 训练 + 维护奖励模型 | 构造可靠的判定器 |
| 主要风险 | 奖励黑客、分布外外推 | 判定器本身可能不完备 |

两条路的适用边界，也解释了 GRPO 为什么先在数学和代码上跑通：可验证信号让「对同一个 prompt 采样一组答案并比较」变得廉价且客观，而这正是 GRPO 估计优势所需要的东西。GRPO 最早提出的场景（DeepSeekMath）就是纯数学任务，这并不是巧合。

需要留意的是，这不代表 RL 本身变强了，**是可验证的那部分任务先被攻下来了**，而开放性任务仍然要回到奖励模型，或借助更细致的结构化评价——后者在第四章的 rubric reward 一篇里会继续展开。

### 2.3 三种做法的分野与演进

PPO、DPO、GRPO 常被当成三个并列选项，但其实它们改的环节不同，出现也有先后顺序：

| 方法 | 出现 | 改了什么 | 留下了什么 |
|-|-|-|-|
| **PPO** | 2017 提出，2022 随 InstructGPT 成为 RLHF 标配 | 让「从人类偏好里学习」第一次能稳定收敛 | 要同时维护策略、价值、奖励、参考四个模型 |
| **DPO** | 2023 | 去掉奖励模型与在线采样，把 RLHF 压成一步监督学习 | 只能学已有偏好数据分布内的东西 |
| **GRPO** | 2024 | 去掉价值模型，用组内归一化估计优势 | 长程任务上，组内比较的粒度不够细 |
| **DAPO / GSPO** | 2025 | 修 GRPO 的熵坍塌、token 级损失偏差与重要性采样粒度问题 | 工程细节更多，离入门更远 |

这张表能解释第三章那个看起来矛盾的现象——GLM-5.2 在长程 Agentic RL 上又从 GRPO 回到了 PPO。这并不能说明 PPO 优于 GRPO ，只是任务条件变了：轨迹变长、结构差异变大之后，「组内归一化」这个粗粒度的优势估计不再够用。

**DPO 的位置需要单独说明**：它不在 2.1 那条链路里。PPO 和 GRPO 都是边生成边改——先采样、再打分、再更新，循环往复；而 DPO 是离线的，直接用「这两个答案里更喜欢哪一个」的偏好数据来改写损失函数，相当于照着一份已标注优先级的样本集直接订正，没有采样这一步。

它换来的是简单、稳定、不需要奖励模型和在线推理；代价是模型只能在已有偏好数据的分布内被调整，学不到数据之外的探索——这一点让它在需要探索的任务上逐渐让位于 PPO / GRPO 路线。

[《DPO 是如何简化 RLHF 的》](https://zhuanlan.zhihu.com/p/671780768)可以帮助理解这种思路。

**算法入口怎么选**：[《人人都能看懂的 PPO 原理与源码解读》](https://zhuanlan.zhihu.com/p/677607581) — 猛猿 · 🟢 是这份清单里赞同最高的一篇，从直觉一路讲到源码，可作为 PPO 的学习入口。想先建立整体感觉，可以从 [《看完能和外婆解释的 PPO、DPO、GRPO 强化学习》](https://zhuanlan.zhihu.com/p/1984387073625593089) — Ryann · 🟢 开始，一篇覆盖三个算法的内容。想从代码层面看组内优势具体怎么算，可以配合 [《强化学习小白理解 GRPO（二）：GRPO 核心代码实践》](https://zhuanlan.zhihu.com/p/23349133287) — wuxiaojun · 🟣 来看。

另外补充一点：严格来说，LLM 上的 PPO 和 GRPO 都不是纯 on-policy——一批 rollout 会被切成多个 mini-batch 做多轮更新，后面几个 mini-batch 的数据其实来自稍早的策略，属于 near-on-policy。这个偏差正是第三章「异步训练带来策略滞后」要处理的问题之一。

## 三、RL 如何在工程实践中转化成模型能力？

> [!IMPORTANT]
> **本章问题**：算法之外，真实场景里还要多搭多少东西？

前两章把「采样—打分—估计优势—更新」这条链路拆清楚了。这一章看它在真实场景里会被撑成什么样——链路本身没变，但每一环都要外挂一整套工程。

今天的 RL 后训练，已经不是「准备数据、跑一个算法、看分数」的流程。尤其在代码、搜索、浏览器操作等 Agent 任务中，模型需要进入真实或模拟环境，连续多步行动后再拿到反馈。更接近现实的理解方式，是把它看成一条能力生产链：

**把真实工作变成任务 → 让模型在环境中尝试 → 让训练系统跑得动 → 验证能力是否真的提升**

### 3.1 先把真实工作变成可训练的任务

模型不会天然地知道怎样修复一个代码仓库、在网页上完成一笔操作，或在复杂工具链中持续推进任务。行业实践的第一步，是把真实工作转化成可练习的训练环境：任务从哪里来、工具如何提供、环境怎样搭建、成功与失败如何判定、完整行动轨迹怎样被记录。

[《Agentic 能力从哪里来？拆解基座大模型的训练过程》](https://zhuanlan.zhihu.com/p/2015552122071037375) — 低级炼丹师 · 🔵 适合作为这一环的入口。它以 GLM 为主线，也提到 MiniMax、Kimi 等实践，讨论了任务合成、环境合成、反馈合成和轨迹合成。读完后能建立一个判断：Agentic RL 的训练数据不是问答对，而是由任务、工具、环境状态和行动过程共同构成的「可练习世界」。

### 3.2 再让模型在环境中尝试

任务和环境就位之后，模型才有机会通过真实行动去学习。

在数学、代码等短程任务中，答案的对错、单元测试是否通过，通常能提供相对明确的反馈；但在长程 Agent 任务中，模型可能需要连续调用工具、处理环境变化、规划几十步甚至更多步骤。它很可能在早期就走错，却要到任务结束时才看到失败结果——这正是 2.3 提到的「组内比较粒度不够细」问题的来源。

[《GLM-5.2 为什么在 long-horizon Agentic RL 上从 GRPO 回到 PPO？》](https://zhuanlan.zhihu.com/p/2050537350888002209) — ThisIsSoMe · 🔵 是一个很典型的观察窗口。它说明，GRPO 在短程、可验证任务中的组内比较很有效；但当任务变成长程 Agent，轨迹长度和结构差异变大，训练又需要更细致地判断「是哪一步导致成功或失败」。PPO 和 GRPO 在这里的被使用不是简单的新旧替代，企业往往根据任务的条件会做不同的选择——对照 2.3 那张演进表，这个来回就不显得突兀。

### 3.3 让训练流水线真正跑起来

Agentic RL 的难点不只在模型。一次训练里，rollout 要生成长轨迹，环境可能依赖 CPU、沙箱和网络，训练需要 GPU，奖励还可能来自规则、测试或另一个模型。不同环节的速度和资源需求不一样，如果仍然绑在一条同步流水线上，大量算力会消耗在等待上。

[《从各家技术文章看 26 年 Agentic RL Infra 优化方向》](https://zhuanlan.zhihu.com/p/2007250216227729670) — attack204 · 🔵 横向讨论了 MiniMax Forge、ROLL、Kimi Seer 等系统的探索：将 Agent、rollout、奖励和训练解耦，用异步调度、前缀缓存复用和长轨迹管理提高吞吐。它能帮助理解，Agentic RL 已经不只是算法问题，也是一类分布式系统问题。

[《用 RL 做 LLM 后训练：半年踩过的坑与心得》](https://zhuanlan.zhihu.com/p/1986921621240447760) — 天晴 · 🟣 则把这些系统问题放回具体的实验现场：rollout 和训练如何同步、环境成本为什么会成为瓶颈、训练和推理不一致为什么会破坏稳定性。它给出的判断是，RL 的效果不只取决于算法，也取决于数据、环境和系统能否真正配合。

> [!NOTE]
> 这一节涉及的系统细节（角色解耦、权重同步、异步带来的策略滞后与背压），在本系列第一册《AI Infra 蓝宝书》第四章中有更完整的展开。

### 3.4 最后，模型学到的真的是想要的能力吗？

训练分数上涨，和模型在真实场景中变得更好并不是一回事。这一节的三篇，分别对应三种典型的落差。

**跨环境的稳定性**：Agent 需要在不同工具、不同 Code IDE 中保持稳定的表现。[MiniMax 算法工程师在「如何评价 MiniMax-M2」问题下的后训练分享](https://www.zhihu.com/question/1965302088260104295/answer/1966524554693288083) — Junheng · 🔵 提出的目标很有代表性：模型不应只适应某一个固定环境，而要能应对工具、系统提示、环境状态等整条行动轨迹上的变化。

**奖励与目标的错位**：[《Claude Code 模型 RL 训练中的 Reward Hacking》](https://zhuanlan.zhihu.com/p/2026679461102330722) — skydownacai · 🔵 讨论的正是 2.2 里提到的风险如何变成现实：当评价方式只抓住表面信号，模型能获得高奖励，却没有真正完成任务。

**新能力与已有能力的冲突**：一个统一模型要同时保留数学、代码、Agent 和日常对话等能力。[《聊聊 DeepSeek-V4 中后训练部分，一些共识有效的经验》](https://zhuanlan.zhihu.com/p/2031833031347057876) — 曾天真 · 🔵 解读的「分领域训练、再合并能力」路线，以及 [《从技术报告看 On-Policy Distillation 的崛起：大模型后训练新范式》](https://zhuanlan.zhihu.com/p/2031101471563962191) — 潜龙勿用 · 🔵 讨论的更丰富反馈方式，都在回应同一个问题：模型学习新能力时，怎样避免丢掉已经具备的能力。

从行业实践来看，RL 正在从「让模型回答得更好」走向「让模型在真实环境中完成任务」。支撑这件事的不只是一种新算法，而是一整套围绕任务、轨迹、反馈和系统建立起来的训练方式。

## 📖 术语速查

| 术语 | 含义 |
|-|-|
| RL（Reinforcement Learning） | 强化学习：靠奖励信号调整生成概率的机制 |
| Rollout | 用当前策略采样生成一批输出 |
| Reward | 奖励：对单条输出的标量评分 |
| Policy | 策略，即被优化的模型本身 |
| Advantage | 优势：单条输出相对于基线（价值模型预测值或组内均值）好多少，驱动更新的量 |
| Value Model / Critic | 价值模型：预测给定前缀下后续期望收益，用作优势基线；GRPO 省掉了它 |
| KL（Kullback–Leibler） 惩罚 | 约束新策略与参考模型分布距离的项，抑制能力退化与奖励黑客 |
| RLHF（Reinforcement Learning from Human Feedback） | 基于人类反馈的强化学习，奖励来自偏好模型 |
| RLVR（Reinforcement Learning with Verifiable Rewards） | 可验证奖励强化学习，奖励来自程序化判定 |
| Reward Model | 奖励模型：用偏好对训练的打分模型 |
| Verifier | 验证器：判定输出是否符合客观标准的程序 |
| PPO（Proximal Policy Optimization） | 近端策略优化：clip 限幅 + KL 惩罚，更新保守 |
| DPO（Direct Preference Optimization） | 直接偏好优化：离线方法，直接用偏好对改写损失函数 |
| GRPO（Group Relative Policy Optimization） | 组相对策略优化：用组内归一化替代价值模型 |
| On-policy | 用于更新的数据来自当前策略 |
| Off-policy | 用于更新的数据来自其他（或更早的）策略 |
| Near-on-policy | 一批 rollout 切成多 mini-batch 多轮更新，后段数据来自稍早的策略 |
| Reward Hacking | 奖励黑客：模型获得高奖励却未完成真实目标 |
| Entropy Collapse | 熵坍塌：训练中多样性下降，输出趋于同质 |
| Rubric Reward | 量规式奖励：把质量标准拆成多条可判定的评分项 |
| On-Policy Distillation | 在线策略蒸馏：在自己的生成轨迹上接受教师模型反馈 |
| Agentic RL | 智能体强化学习：在环境中连续多步行动、延迟反馈的 RL |
